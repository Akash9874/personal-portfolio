Project 01

Collaborative Code Review Sandbox

Edit code together, draw on it, run it. Nothing to install.

The idea

Code review lives in comment threads. The explaining happens on a whiteboard somewhere else. I wanted both in one browser tab.

What I built

A shared workspace where several people edit the same files, sketch boxes and arrows straight over the code, and run it to see the same output at the same moment. Edits sync through a Yjs CRDT over WebSockets, so two people can work offline and still merge cleanly when they reconnect.

The hard part

A drawing has to stay with the code it describes. Add ten lines above a function and the box around it moves down too. Delete the code and the drawing dims. It never slides onto something unrelated.

The decision I'd defend

Syncing and running code are two separate services. One only relays edits and never looks inside them. The other validates, rate-limits and runs code in isolated containers.

Project 02

Enterprise RAG with Guardrails & Evaluation

An AI assistant you can attack, measure and trust, built on a laptop with no GPU.

The constraint

One rule from the start: no usable GPU, 16 GB of RAM, and no budget for paid inference.

What I built

A question-answering service where every request passes through a chain of safety checks, cheapest first. Pattern and personal-data checks take under a millisecond. Small classifier models run next. A language model is only called when the cheaper checks can't decide.

How I know it works

I attacked it. 22 attacks, plus 12 harmless questions as a control group.

The part I'm proudest of

Scoring uses no AI judge, so the same commit gives the same score on my laptop and in CI. When I planted a regression on purpose, recall dropped from 0.661 to 0.464 and the build failed, as designed.

5 of the 22 attacks succeeded, and 4 of those were unanswerable questions it hedged on when it should have refused. Answers take 34.6 seconds against a 20-second target. 57% of answers cite no source. Each of these is written up in the repo with what it would cost to fix.

Project 03

Focus Timer

A gentle daily time budget for distracting sites. A Chrome extension with no dependencies.

The idea

Blocking a site outright is all or nothing. This gives it a daily allowance instead. A small countdown pill shows what's left, and when the allowance runs out the page blurs behind a reminder.

The detail I like

You can borrow five minutes, but it's a loan and not a reset: tomorrow starts five minutes shorter.

The hard part

Chrome shuts down an extension's background worker after about 30 seconds idle, so a running counter would quietly lose time. Time is worked out from saved timestamps instead, and each save is capped at 90 seconds so a sleeping laptop can't add phantom hours.

Only when you're there

The clock pauses when you switch tabs, leave the window, or stop touching the keyboard for 60 seconds.

Project 04

QuickMart

Compare the price of the same groceries across stores, and see the best deal.

The idea

One place to compare what the same item costs at several quick-commerce stores, with the cheapest one marked and the saving worked out.

What I built

A Next.js app on PostgreSQL with Prisma. You browse by category or search, each product lists its price at every store, the lowest is highlighted, and the saving shows as a percentage. Accounts, a cart and orders run through the app's own API routes.

What it doesn't do yet

The stores and prices are sample data seeded into the database, not live feeds from real retailers.

Act IIIProve

If it's true, it should survive review.

2026 9th International Conference on Intelligent Computing and Control Systems (ICICCS), IEEE Xplore, pages 1239–1245

Federated Learning for Privacy Preservation of IoT Device

First author, with Sai Suraj Voleti, Adithya P and Jasmine S.

The problem, plainly

Phones and sensors can train a shared model without their data ever leaving the device. The trouble is real devices. Some are slow, some are low on battery, some drop offline halfway through. Waiting for all of them stalls everyone.

What we designed

An asynchronous approach. The server takes updates as they arrive and gives late ones less weight. It chooses which devices to train on, and devices low on battery do less work each round. Each update gets noise added on the device for differential privacy, then is compressed to save bandwidth.

Result

Tested on human-activity sensor data, with each device holding a different mix of data, it reached accuracy comparable to centralized training and outperformed synchronous federated learning when the devices were uneven.
